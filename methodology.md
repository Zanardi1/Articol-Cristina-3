# Experimental Methodology

## 1. Research Objective

This study compares five facial-recognition classification pipelines using the Labeled Faces in the Wild (LFW) dataset:

1. Scikit-learn PCA + Support Vector Machine (SVM)
2. FaceNet embeddings + SVM
3. VGG-Face embeddings + SVM
4. ResNet101 features + SVM
5. Dlib face embeddings + k-Nearest Neighbors (KNN)

The comparison evaluates classification accuracy, macro-averaged F1 score, and class-specific performance across five stratified train/test partitions.

For the Dlib pipeline, face-detection coverage and end-to-end accuracy are additionally evaluated.

The experiment is a closed-set identity-classification task involving seven known individuals. It does not evaluate open-set recognition, unknown-identity rejection, or face verification.

## 2. Dataset

The experiments use the LFW dataset, loaded through `sklearn.datasets.fetch_lfw_people`.

The following parameters are applied:

| Parameter | Value |
|---|---|
| Dataset | Labeled Faces in the Wild |
| Minimum images per individual | 70 |
| Image resize factor | 0.4 |
| Total images | 1,288 |
| Number of identities | 7 |
| Image dimensions | 50 × 37 pixels |
| Original image representation | Grayscale |

The seven identities are Ariel Sharon, Colin Powell, Donald Rumsfeld, George W. Bush, Gerhard Schroeder, Hugo Chavez, and Tony Blair.

The dataset loader provides the image data, numeric class labels, and class names. All five pipelines use the same selected dataset.

## 3. Experimental Design

Five stratified holdout evaluations are performed using the random seeds:

`42, 123, 2024, 2025, 2026`

Each evaluation uses an 80% training partition and a 20% test partition:

- Training images: 1,030
- Test images: 258

Partitions are generated using `train_test_split`, with `stratify` set to the dataset labels.

The same original image indices define the training and test partitions for all five algorithms within each seed.

The partitions generated by different seeds may overlap. Consequently, the five evaluations are repeated stratified holdouts rather than five independent datasets or conventional five-fold cross-validation.

For the pretrained deep-learning pipelines, feature extraction is performed on the selected images before the train/test partition is applied to the extracted features. The pretrained feature extractors are not fine-tuned using the LFW training partitions.

Classifier fitting uses the training partition, while reported classification metrics are calculated on the corresponding test partition.

## 4. Facial-Recognition Pipelines

### 4.1 Scikit-learn: PCA + SVM

The baseline pipeline operates on flattened grayscale images.

Its processing stages are:

1. StandardScaler normalization.
2. Principal Component Analysis (PCA).
3. Support Vector Classification using a radial basis function (RBF) kernel.

PCA uses 150 components, randomized singular-value decomposition, whitening enabled, and random state 42.

Hyperparameter selection uses `RandomizedSearchCV` with 10 sampled configurations and five-fold cross-validation.

The search distributions are:

- SVM regularization parameter C: log-uniform distribution between 1,000 and 100,000.
- RBF gamma: log-uniform distribution between 0.0001 and 0.1.

The SVM uses balanced class weights.

Standardization and PCA are included inside the cross-validation pipeline so that their fitted transformations are learned from the corresponding training folds.

The selected configuration is refitted on the training partition and evaluated on the test partition.

### 4.2 FaceNet: InceptionResnetV1 + SVM

The FaceNet implementation uses the `facenet-pytorch` library and the `InceptionResnetV1` architecture.

The model is initialized using pretrained `vggface2` weights.

Input images are processed as follows:

1. Grayscale images are replicated across three channels.
2. Images are resized to 160 × 160 pixels.
3. Pixel values are normalized using channel-wise mean 0.5 and standard deviation 0.5.
4. The pretrained network extracts facial embeddings.

The network operates in evaluation mode, without gradient computation, and the implementation explicitly performs embedding extraction on the CPU.

A linear-kernel SVM is trained on the extracted embeddings, with probability estimation enabled.

No FaceNet fine-tuning is performed on the LFW dataset.

### 4.3 VGG-Face + SVM

The VGG-Face pipeline uses the `DeepFace` library.

Grayscale LFW images are converted into three-channel images, resized to 224 × 224 pixels, and scaled to the 0–255 pixel range.

Embeddings are extracted using `DeepFace.represent`, configured with:

- Model: `VGG-Face`
- Normalization: `VGGFace`
- `enforce_detection=False`

The implementation uses the representation returned by DeepFace without imposing an additional external face-detection rejection rule.

The extracted embeddings are classified using a linear-kernel SVM with probability estimation enabled.

The pretrained VGG-Face model is not fine-tuned on the LFW dataset.

### 4.4 ResNet101 + SVM

The ResNet101 pipeline uses the Keras implementation of ResNet101 with ImageNet-pretrained weights.

Input preprocessing consists of:

1. Reshaping grayscale images into image arrays.
2. Replicating the grayscale channel to obtain three channels.
3. Resizing to 224 × 224 pixels.
4. Applying the Keras ResNet101 `preprocess_input` function.

The network is instantiated with `include_top=False`, removing its original classification head.

The resulting convolutional feature maps are flattened into feature vectors.

A linear-kernel SVM with probability estimation enabled is fitted on these vectors.

The ResNet101 feature extractor is not fine-tuned on LFW.

Unlike FaceNet and VGG-Face, the ResNet101 pretrained weights originate from general-purpose ImageNet classification rather than a face-specific representation-learning task.

### 4.5 Dlib + KNN

The Dlib pipeline uses a pretrained face-detection and face-recognition system.

Its components are:

- Dlib frontal-face detector.
- Pretrained 68-point facial-landmark predictor.
- Pretrained Dlib ResNet face-recognition model.
- KNN classifier.

The implementation converts the grayscale images to three-channel arrays, scales pixel values to unsigned 8-bit integers, and resizes the images to 148 × 200 pixels.

Face detection is performed with an upsampling parameter of 0.

For detected faces, facial landmarks are estimated, an aligned face chip is generated, and a facial descriptor is extracted using the pretrained recognition model.

The implementation uses the first detected face when multiple faces are present.

Images for which no face is detected do not receive a facial descriptor and are excluded from KNN training or recognition evaluation.

The KNN classifier uses the default parameters of `sklearn.neighbors.KNeighborsClassifier`, including five neighbors.

Detection coverage and end-to-end accuracy are reported to account for the excluded test images.

## 5. Classification Protocol

All five pipelines use the same stratified train/test partition indices for each random seed.

The Scikit-learn baseline trains its preprocessing and classifier pipeline independently for each partition.

For FaceNet, VGG-Face, and ResNet101, pretrained features are extracted once and reused across the five partitions. A separate SVM is fitted for each training partition.

Dlib similarly extracts facial descriptors before the repeated partition evaluations. Only successfully detected images have descriptors available.

The Dlib training and test subsets are formed by intersecting the successfully detected image indices with the original shared partitions.

No classifier is trained using test-partition labels.

## 6. Evaluation Metrics

### 6.1 Classification Accuracy

Accuracy measures the proportion of evaluated test predictions that match their ground-truth labels.

For the four pipelines without explicit detection rejection, the evaluated test set contains all 258 images.

For Dlib, recognition accuracy is calculated only over successfully detected test images.

### 6.2 Macro-Averaged F1 Score

The F1 score is the harmonic mean of precision and recall.

Macro F1 is calculated as the unweighted arithmetic mean of the seven class-specific F1 scores.

This metric gives each identity equal importance, regardless of the number of images associated with that identity.

### 6.3 Per-Class Metrics

Precision, recall, F1 score, and support are recorded for each identity and each random seed.

Confusion matrices are generated separately for each algorithm and seed.

### 6.4 Detection Coverage

For Dlib, detection coverage is defined as:

Detection coverage = Successfully detected test images / Total test images

Detection coverage is evaluated independently for each shared test partition.

### 6.5 End-to-End Accuracy

For Dlib, end-to-end accuracy is defined as:

End-to-end accuracy = Recognition accuracy × Detection coverage

Equivalently, this is the number of correctly classified detected test images divided by the total number of test images.

A test image that fails detection is therefore treated as an unsuccessful end-to-end recognition attempt.

### 6.6 Aggregation Across Splits

For each algorithm, the arithmetic mean and sample standard deviation of the evaluation metrics are calculated across the five random seeds.

Results are reported in the form:

Mean ± Standard Deviation

The standard deviations describe variability across the five selected holdout partitions. They should not be interpreted as confidence intervals or evidence that the partitions are statistically independent.

## 7. Experimental Outputs

The experiment produces the following outputs in the `Results` directory:

| File | Contents |
|---|---|
| `multi_split_results.csv` | Individual algorithm and seed results |
| `multi_split_summary.csv` | Aggregated evaluation metrics |
| `paper_comparison.csv` | Publication-oriented comparison table |
| `class_metrics.csv` | Class-specific metrics for each evaluation |
| `predictions.csv` | Original image indices, labels, predictions, and detection status |
| `confusion_matrices/` | Per-algorithm, per-seed confusion matrices |
| `environment_info.json` | Recorded software and execution environment |

The prediction-level records retain original dataset indices, allowing results to be compared across algorithms for the same test images.

For Dlib, failed detections are explicitly recorded with the status `detection failed`.

## 8. Limitations and Interpretation

### 8.1 Restricted Dataset

The selected LFW subset contains only seven identities, each with at least 70 available images.

The results therefore characterize performance on this restricted closed-set classification problem and should not be generalized directly to large-scale or open-set facial recognition.

### 8.2 Pretrained Models

FaceNet, VGG-Face, ResNet101, and Dlib use pretrained representation models.

Their results measure the effectiveness of the pretrained representations combined with the specified classifiers, rather than the ability to learn facial representations from scratch using the selected LFW training images.

Possible overlap between face-specific pretraining datasets and LFW has not been independently ruled out.

### 8.3 Detection Failures

Dlib's conditional recognition accuracy is not directly comparable with full-test-set classification accuracy unless its detection coverage is considered.

End-to-end accuracy provides an additional measure that incorporates failed detections.

### 8.4 Repeated Holdout Evaluation

Five stratified holdout partitions are used rather than an independent external test dataset.

The resulting measurements provide descriptive evidence of performance variation across these partitions, but do not establish generalization to other datasets or deployment environments.

### 8.5 Computational Comparability

The pipelines differ in architecture, input processing, pretrained training data, feature dimensions, and classifier choice.

The experiment compares complete implemented pipelines, not the isolated effect of individual neural-network architectures.

Computational efficiency should not be inferred from the classification metrics alone.

## 9. Reproducibility

The experiment uses centralized configuration values in `experiment_config.py`, with the main five-split evaluation implemented in `multi_split.py`.

The experiment can be launched using:

```bash
python main.py
```

The publication comparison table can be regenerated from the saved numerical results using:

```bash
python report_results.py
```

Software versions are recorded in `requirements.txt` and `Results/environment_info.json`.

The environment information is a snapshot captured separately from the model evaluation. Exact pretrained-weight provenance, file checksums, and hardware characteristics should be recorded separately when available.
